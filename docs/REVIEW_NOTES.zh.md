标记含义：**事实性纠错**是与已取得源码不符或表述超出证据；**结构调整**是依赖、范围或实现选择改变；**新增**是原计划缺失的契约和验收。P0 表示会导致账务、证据或产品目标失真；P1 表示关键实现/验收风险；P2 表示文案和追溯改进。严重程度不表示已在生产发生事故。

## 草稿第 2 节：改造方案

### 2.1 中文 UI

- **结构调整 / P2**：保留多语言基础，默认中文、模拟原话可繁体/夹英文、报告解释用简体；“全中文 UI”不等于把真实引用强行翻译。
- **新增 / P1**：加入同源 API、移动端检查、中文配置错误、纯文本渲染、取消/缺失/费用显示。build 成功不能替代浏览器验收。
- **新增 / P1**：已读到 Flask CORS `*` 与 debug 请求体日志。规划单机 loopback、限制 CORS、去正文日志；远程服务另做认证隔离，不能沿用开发服务对公网裸开。

### 2.2 模型层与费用

- **结构调整 / P0**：从事后 usage.json/token 计数改成持久的出站前费用预留；账本写入与配额争抢在同一事务中完成。
- **新增 / P0**：美元价格表、供应商缓存/推理计费语义、未知 usage、超时未知收费、SDK 隐藏重试、断电恢复、日预算、并发上限、报告保留额度和配置 fail closed。
- **事实性纠错 / P1**：“让供应商决定人设/报告输出上限”取消；各角色都有有界输出，所有修复请求计费，不能用任意去上限重试。
- **新增 / P1**：执行开发工作的 Cursor/Codex 模型与产品运行时 API 型号分开。运行时推荐供应商分工，但不编当前账号权限、价格或未测的便宜程度。
- **新增 / P1**：冷人设缓存与热缓存两套成本，明确公式和纯算术示例；在模型价格未知时不把示例数当承诺。

### 2.3 本地替代 Zep

- **结构调整 / P1**：拆分“推文不建图”与“通用图谱替代”两种工作。前者是早期可用版本，后者仍是完整目标的必做 M6。
- **新增 / P0**：抽取失败块保留、可重试、partial 状态、来源跨度、实体冲突、时间有效性、并发写入、幂等和删除联动；取消“失败块直接丢弃”。
- **事实性纠错 / P1**：FTS5 的 unicode61 不等于中文分词；trigram 也不能直接覆盖所有两字查询。加入中文分词、索引归一化、短查询测试和可测召回率。
- **结构调整 / P1**：初版不加 embedding；“已经装 sentence-transformers”不代表已选好中文模型、模型许可证、下载和资源开销。
- **新增 / P1**：旧云项目保留后端标识，不随默认值自动迁移/删云图；新本地路径要切断 import、启动、报告和删除中的所有 Zep 硬依赖。

### 2.4 推文模式

- **结构调整 / P0**：选择独立受限动作循环，首版具备真 reply；不再让用户接受用 quote 伪装回复。OASIS Twitter 评论方法存在，但项目端到端回复兼容尚未实测，不能当作依赖已解决。
- **结构调整 / P1**：不估成“一两百行循环”。显式纳入事件持久化、可见时间线、parent/target、去重、预算、取消、恢复和证据验证。
- **新增 / P1**：幂等任务接口、任务状态机、输入长度、未曝光/划走/失败三类区别、作者不参与自聊、草稿不被重写后偷偷注入模拟。
- **结构调整 / P2**：暂不设计通用插件系统，只保留清晰模式边界；游戏/播客/续写不扩大首版范围。

## 草稿第 3 节及四个提示词：工程化重写

### 人设模板

- **结构调整 / P0**：原配额把 fan、troll、rival、casual 等关系/行为混成单一角色，且默认 8 个明确反对、仅 6 个 ignore。改为 12 主圈层 + 独立关系/活跃/语言/影响力/态度/地域等边际配额，按最大余数法与有种子洗牌生成槽位。
- **新增 / P1**：覆盖科技、币圈、海外、大陆翻墙、港台、键政、女权/反女权、段子、营销、KOL、路人、机器人；明确是场景先验，没有真实人口统计依据，身份不决定立场。
- **结构调整 / P1**：人设生成不看当前草稿，避免每个人都被塑造成恰好被触发。批量短人设，固定槽位由程序合并，模型不能改配额；不再一次输出 24×200 字却给不够的统一 800-token 上限。

### 行动模板与调度

- **结构调整 / P0**：将沉默建成显式概率与事件：90% none、7% like、1.5% reply、0.8% repost、0.7% quote 候选先验，可按活跃度调整并归一化，模型只能执行候选或放弃。
- **结构调整 / P0**：删除“没有反对就必须叫醒反对者”、每轮补怀疑者和“必须两种 stance”的验收。保留样本多样性，同时允许真实结果一致，避免反向造假。
- **结构调整 / P1**：默认 24×4 改为 120 个曝光样本、3 个不重叠波次，多数无需 LLM。扩大沉默分母而不靠 120×3 次调用；同时说明候选机制限制传播上界，必须与先验基线比较。
- **新增 / P1**：HTTP 并发与多 persona 单请求区分；行动独立上下文、同波不可相互观察、不可见/未来 ID 拒绝；temperature 不被当作防复读保证。
- **新增 / P0**：失败不能填 none；top_replies 不能拿 quote 补数。少量账号真实冒烟不再强求恰好产生“划走+发言”，以免低概率事件让验收随机失败。

### 报告模板与 schema

- **结构调整 / P0**：初稿只是 JSON 形状示意，缺完整 schema；新增 Draft 2020-12 报告 schema，字段完整必填、枚举/范围/额外字段/complete 与 degraded 条件全部定义，另有 persona/action schema。
- **新增 / P0**：触发句具备原文跨度、群体、反应类型与 action_id；验证支持关系而不只验证 ID 存在。高赞回复有实际模拟点赞、被展示次数、排序依据与局限。
- **结构调整 / P0**：删除“划走 >70% 一律 low”的阈值。它与沉默占多数的目标冲突，会把大多数正常结果锁成 low。改为程序计算原帖独立互动率，明确分母、缺失区间、最小曝光和 insufficient_data。
- **新增 / P1**：风险等级规则化并有证据；沉默不算支持，少数派保留原话；改写给出收益与代价并标未重跑，不虚构提升效果。
- **新增 / P1**：置信度初版 low，不制造精确概率；真实校准状态、受众假设、上下文缺失、样本与环境未知持续可见。
- **结构调整 / P0**：一次修复仍失败时不能“删几个字段继续当成功”。complete 必须 2–3 个改写；降级可缺改写，但状态、原因和计数真实，并通过同一 schema。
- **新增 / P1**：提示注入隔离、变量 JSON 序列化、Unicode 码点跨度、输出上限、无思维链、合成 few-shot/反例与可执行契约验证。

## 草稿第 4 节：里程碑

原顺序把角色/费用、UI、推文、本地记忆穿插，但无 Zep 启动、状态恢复和 eval 契约没有独立前置门槛。现调整为：

`M0 基线与契约 → M1 启动/持久任务 → M2 provider/费用 → M3 人群/循环 → M4 报告/eval → M5 中文 UI → M6 本地图 → M7 历史验证/发布`。

- **结构调整 / P1**：M0 开始设计固定集与收集数据；M7 依赖 M6，避免“推文能跑”就宣称完整改造完成。
- **新增 / P1**：每个里程碑给出低/中/高/很高体系内的难度与用户指定执行模型，只使用 grok-4.7、gpt-6-sol、gpt-6-astra high/xhigh，并说明任务匹配理由。
- **结构调整 / P1**：mock、真实供应商冒烟、历史质量、UI 浏览器和部署验收分开。无密钥可以完成确定性工作，但不能将真实能力勾成通过；测试数量不锁死为 130。
- **新增 / P1**：费用并发抢占、unknown usage、三份 OASIS 脚本、中文短词检索、旧图删除不误伤都进入可复现验收。

## 草稿第 5 节：评估框架

- **结构调整 / P0**：原来 8–12 条凭记忆的定性样本只适合探索，不能支持与真实反响对比。改为 30 条有授权与来源快照的真实推文，20 dev/10 holdout，标签与输入隔离；明确当前数据未提供，绝不伪造。
- **新增 / P1**：统一或分组观察窗口、曝光与作者基线、缺失值不填零、去重防泄漏、模型训练污染标记、双人风险标注与裁决。
- **新增 / P1**：同 seed N=5 的一致率/方差/跳档阈值，另设不同 seed N=10 测抽样波动；不能将“差一档也算稳定”当作无条件成功。
- **新增 / P1**：macro-F1、ordinal MAE、相关性、high 风险召回、触发跨度 F1、回复主题命中、人审保意、新事实率、费用/延迟分位数及基线比较。
- **结构调整 / P1**：立场熵是诊断，不设最低熵强行造反对。低争议样本可一致；历史集结果不足以证明真实传播预测时保留实验定位。
- **新增 / P1**：prompt/model/schema/配额/价格/检索变化都触发版本化回归；先过证据和费用硬门禁，再看质量；holdout 不循环调参。

## 许可证与原第 6 节

- **事实性纠错 / P1**：不把 AGPL 简化为“给别人用就必须向所有人公开”或“禁止商业服务”。区别私有使用、分发义务、修改版网络交互的对应源码提供义务；源码要对应实际服务版本，不仅是上游链接。来源见 [GNU AGPLv3](https://www.gnu.org/licenses/agpl-3.0.txt) 和[仓库 LICENSE](https://raw.githubusercontent.com/666ghj/MiroFish/main/LICENSE)。
- **新增 / P1**：源代码许可证与推文数据/头像/商标、供应商条款不混为一谈；公开服务的认证隔离与许可证义务分别验收。
- **事实性纠错 / P2**：用户描述为 8 个问题，下载草稿第 6 节实际列 9 条；已全部纳入，未漏掉单机/对外使用那一条。下方合并为 13 个不重复决策。

## 本次验证结果与未核实事项

已实际执行：3 个 schema 的元 schema 检查；5 个合法输出样例；6 个结构反例、5 个证据反例拒绝；完整 120 条合成事件的计数、原文跨度、群体、回复点赞/曝光一致性；配额与成本算式复核；draft 文件哈希未变化。验证脚本为 [validate_examples.py](prompts/validate_examples.py)。审查时的完整输出记在审查工作区的 artifact_validation.txt，该文件没有放进本仓库。这不等同应用测试，更不证明自然语言解释正确。

已查源码：前后端入口与语言、存储/任务、主要 LLM 调用点、Zep 读写搜删、OASIS/CAMEL 版本及关键接口、脚本选择、依赖、环境变量、镜像和启动方式。完整本次来源表见 [定稿第 1 节](DEV_PLAN.zh.md)。

未核实/未实测：上游固定 commit、fork 全仓差异、草稿自述测试和 npm 审计、真实 Docker/Zep/OASIS 端到端、Twitter 评论在本应用的全链路、供应商具体账号型号/费用/延迟/效果、历史推文结果与任何预测准确率。保留的风险判断是源码推断或设计约束，不是生产事故复现。
