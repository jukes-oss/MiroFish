# 轮次调度契约 v1（规则实现，不调用模型）

这里没有一个“主持舆论”的模型。调度只控制曝光、可见时间线、候选动作和预算；不能依据上一轮是否有反对意见补人、补观点或补回复。

1. 用记录的 `seed` 派生 `slots_seed, persona_seed, exposure_seed, candidate_seed, timeline_seed`。供应商 seed 若可用也记录，但不承诺模型确定性。
2. 默认 120 个账号随机分为 3 波，每波 40；余数均匀分配。每账号只获得一次原帖曝光。槽位低活跃也会被曝光，区别是行为概率更低；**未曝光不等于划走**。
3. 每波开始冻结只含此前已提交公开动作的时间线；原帖必见，加最多 6 条前波回复/引用（按固定随机抽样及关系权重，不按支持/反对标签筛选）。同波并行账号互不可见。本轮所有结果落库后才进入下一波。
4. 根据 `audience.zh.md` 候选分布抽样。候选 none → 写 `source=rule,outcome=completed,action=none`；其他候选 → 单账号请求模型，最多执行候选动作或放弃。绝不把所有账号放进一个共同对话。
5. 每次请求前取得费用预留，默认并发 4，全运行最多 60 次物理行动请求（含重试），总请求另有限制。达到上限的已曝光账号记 missing，未启动的后续波不伪造曝光。取消与失败同理。
6. 行动落库校验 `target_id` 在该账号 `visible_ids` 内。reply、repost、quote 的目标只能是 `post_0`；like 可指向原帖或可见回复/引用；none 的目标为空。禁止自赞、重复赞、未来事件 ID。
7. 记录每条回复被多少独立账号看到及收到的有效点赞。没有可比曝光或点赞时只能列“回复候选”，不得声称高赞已获证实。
8. 一轮零公开动作也继续到配置的下一波；全部 none 也是合法结果。无预算则结束为 degraded，保留真实已完成事件。

## 宿主统计与枚举

`E` = 已曝光独立账号数；`V` = 完成有效动作（含 none）的独立账号数；`M=E-V` = missing。
`A` = 对 `post_0` 执行 like/reply/repost/quote 的独立账号数；一人至多一个动作，故不重复计数。
`engagement_rate=A/V`（V=0 时为 null）；另给未知动作区间 `[A/E,(A+M)/E]`（E=0 时为空）。点赞回复不计原帖互动。
`none_rate=none/V`；只点赞、沉默、缺失与未曝光分别显示。对立场的统计只统计 reply/quote 的有效文字表达，不从粉丝身份、点赞或沉默推断支持。

档位是当前抽样假设下的模拟互动档，未用历史数据校准前不是现实传播档：

- 数据足够：`E >= 80` 且 `V/E >= 0.8`，且缺失区间的上下端不跨档；否则 `insufficient_data`。
- `low`：rate < 0.03；`medium`：0.03 ≤ rate < 0.08；`high`：rate ≥ 0.08。
- 数值边界用整数交叉相乘处理，不因小数格式化跨档。阈值和先验一起版本化；不得为了某篇报告更好看修改阈值。

风险规则 `risk_rules_v1`（校准前仅提示可能性）：

- 曝光/完成比例不足同上，或 missing 占已曝光 > 0.05 → `insufficient_data`，但仍列出已有风险证据。
- 至少 3 个不同账号明确负面 reply/quote，来自至少 2 个 `primary_group`，且引用同一原文触发跨度 → `high`。
- 有明确负面 reply/quote，但未达 high → `medium`。
- 无明确负面表达 → `low`，必须说明“本次未观察到，不等于无风险”；不能把讽刺误判成正面后直接给安全保证。

上述计数与标签由程序确定，模型解释原因，不得覆写。讽刺和负面语义仍有模型误判风险，历史标注及人审负责发现此问题。对小样本不要设置“立场熵必须大于某值”的门禁；一致意见可以真实发生，强行多样化反而造假。
