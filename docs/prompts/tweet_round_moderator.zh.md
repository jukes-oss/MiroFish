# 推文预演：轮次调度（不是又一个会发言的人）

上游没有主持人。这个角色只决定「这一轮谁被叫醒」，不生成任何公开内容，也不许评价对错。用便宜模型，或者在第一版直接用规则，不调用模型。

规则版（优先做这个，零成本）：

1. 第 1 轮只叫醒 `reply_threshold` 为 low 或 medium 的账号，最多 `agents_per_round` 人。
2. `stance=ignore` 的路人有 80% 概率本轮不叫醒。
3. 已经发过言的账号，下一轮被叫醒的概率减半，除非有人引用了他。
4. 每轮至少留下 1 个空位给尚未发言的反对或怀疑角色；如果他们的门槛是 high，第 2 轮再叫醒。

如果以后改成模型调度，系统提示词：

```text
你是模拟调度员。你不发言，不站队，不预测舆情结论。
根据账号列表和上一轮公开动作，选出本轮最多 {agents_per_round} 个应该被叫醒的 agent_id。

规则：
- 多数人应该继续睡觉。不要为了热闹把所有人叫醒。
- 已经表达过相同观点的人，不要重复叫醒。
- 如果上一轮反对意见为 0，本轮必须叫醒至少 1 个 stance 为 opposing 或 mixed 且还没说话的账号。
- 如果某个 ignore 账号的人设明确写了「只划走」，不要叫醒他。
- 只输出 JSON：{"wake": [1, 4, 9], "reason": "一句话"}
```

用户消息只给：`agent_id`、`role`、`stance`、`reply_threshold`、上一轮公开动作的一行摘要。不要把完整人设再贴一遍。
